## session

### `session_status`: Session status

*read*

Whether this server is logged in to Kite, and what to do if it is not. Call this first: Kite sessions end
every day at 06:00 IST.

Returns `logged_in`, the token's `expires_at` and `minutes_left`, `auth_mode` (managed: this server does the
daily login; external: another program keeps the token file and this server only reads it),
`login_managed_here`, the token file path, `minutes_to_token_reset` (to the next 06:00 IST), and a one-line
`safety` summary (trading mode, read-only). The token itself is never shown.

verify=true also makes one live call to Kite and adds `verify` with the user id or Kite's error. Use it when a
token that looks valid might have been ended elsewhere (logging in again with the same API key, or a master
logout on the Kite web, ends the earlier token).

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `verify` | boolean |  | `false` | also ask Kite once (GET /user/profile) whether it still accepts the token, and report the account's user id or Kite's error |

### `login`: Log in to Kite

*auth*

Start the daily Kite login (managed auth mode): returns a one-time login link for the person to open.
Show them the `warning` and the link. They log in at Kite themselves (user id, password, 2FA); never ask for
their credentials and never try to log in for them.

Kite then redirects to the app's registered redirect URL (`redirect_url`). This server completes the login
when that redirect reaches it; if the redirect page cannot be reached, the person can copy the request_token
from the browser's address bar (or the whole URL) and you call complete_login with it.

If a valid token already exists nothing is issued, unless force=true; a new login ends the old token at Kite.
In external auth mode another program owns the login: this only explains and shows the status.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `force` | boolean |  | `false` | issue a new link even though a valid token exists (the new login ends the old token) |

### `complete_login`: Complete the Kite login by hand

*auth*

Finish a Kite login with a request_token the person copied from the browser's address bar after logging in
(use it when the redirect page could not be reached). Exchanges the token with Kite and stores the access
token for every client of this server. Request tokens are single use and last only a few minutes. If
KITE_MCP_ALLOWED_USER_ID is set, a login by any other Kite account is ended and refused.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `request_token` | string | yes |  | the request_token from the address bar after logging in at Kite; the whole redirected URL (which also carries the state) is accepted too |
| `state` | string (optional) |  | `null` | the state from the same URL (optional; if given it must be valid) |

### `logout`: Log out of Kite

*auth*

End the Kite API session, delete the stored token and close any open login link (managed auth mode). Two
steps: the first call (no confirmation_token) only describes what would happen and returns a
confirmation_token; call again with it to do it. Every client using this token is signed out until the next
login. It does not log the person out of the Kite web or mobile apps.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `confirmation_token` | string (optional) |  | `null` | from the first call; omit it to see what would happen and get one |

### `place_gtt_order`: Place a GTT (dry run by default)

*write*

Place a GTT (good till triggered): Kite watches the price and places a LIMIT order when a trigger value is
reached. DRY RUN BY DEFAULT: with dry_run=true (the default) nothing is sent; the answer shows the exact
request, the value of each order, Kite's margin calculation, every safety check and, when live trading is
enabled and the checks pass, a confirmation_token. To create it, repeat the identical call with dry_run=false
and that token.

type=single: one trigger value (not equal to last_price) and one order. type=two-leg is an OCO (one cancels
other): two trigger values, lower first, with last_price between them, and two orders; orders[i] is placed when
trigger_values[i] is reached and the other is dropped (typically a stop-loss below and a target above).
last_price is the current price in INR from get_ltp, get_quotes or get_holdings: never guess it. Only LIMIT
orders are supported; prices must sit on the tick size.

Safety: a GTT uses one slot of the daily order count. Every order is checked against the per-order cap and the
allow-lists; for an OCO only one order can execute, so the day's value grows by the larger order, not the sum.
MCX, CDS and BCD GTTs cannot be valued and so cannot be sent live. Returns the trigger_id when sent.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `type` | `single` \| `two-leg` | yes |  | single: one trigger, one order. two-leg: OCO, two triggers, two orders |
| `exchange` | `NSE` \| `BSE` \| `NFO` \| `BFO` \| `CDS` \| `BCD` \| `MCX` | yes |  | exchange of the instrument: NSE, BSE (equity), NFO, BFO (F&O), CDS, BCD, MCX |
| `tradingsymbol` | string | yes |  | tradingsymbol, e.g. INFY |
| `trigger_values` | array of number | yes |  | trigger prices in INR, on the tick size: ONE value for single; TWO for two-leg, the lower first (trigger_values[i] fires orders[i]) |
| `last_price` | number | yes |  | the instrument's CURRENT price in INR (get_ltp / get_quotes / get_holdings). Kite uses it to decide which way each trigger fires, so it must be fresh |
| `orders` | array of GttOrder | yes |  | the order(s) to place: one for single, two for two-leg |
| `dry_run` | boolean |  | `true` | true (default): validate and preview only, nothing is sent. false: send it live, which needs live trading enabled on the server and the confirmation_token from a dry run |
| `confirmation_token` | string (optional) |  | `null` | the confirmation_token returned by a dry run of this exact call (single use) |

### `create_alert`: Create an alert (dry run by default)

*write*

Create a price alert. DRY RUN BY DEFAULT: with dry_run=true (the default) nothing is sent; the answer shows
the exact request, every safety check and, when live trading is enabled and the checks pass, a
confirmation_token. To create it, repeat the identical call with dry_run=false and that token. Kite allows at
most 500 active alerts per user.

The alert watches lhs_attribute (LastTradedPrice) of lhs_exchange:lhs_tradingsymbol and triggers when
"value operator right-hand side" becomes true (operators: <=, >=, <, >, ==). The right-hand side is a constant
(rhs_type=constant with rhs_constant, in INR for prices) or another instrument's attribute (rhs_type=instrument
with rhs_exchange and rhs_tradingsymbol). Indices live on the exchange INDICES (INDICES:NIFTY 50).

type=simple only notifies. type=ato (alert triggers order) also places the basket `orders` by itself when the
condition becomes true, with no confirmation at that moment: the confirmation you give now covers them. Each
basket order is checked like place_order (per-order cap, allow-lists, tick and lot size) and counts toward the
daily order count and value caps; MARKET orders are valued at the live price plus a buffer (paid market data
needed), MCX/CDS/BCD orders cannot be valued and so cannot be sent live. A simple alert has no orders and no
caps. Returns the created alert (with its uuid) when sent.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `name` | string | yes |  | a label for the alert |
| `type` | `simple` \| `ato` | yes |  | simple: only notify. ato: also place the basket `orders` by itself when the condition is true |
| `lhs_exchange` | `NSE` \| `BSE` \| `NFO` \| `CDS` \| `BCD` \| `MCX` \| `INDICES` | yes |  | exchange of the monitored instrument: NSE, BSE, NFO, CDS, BCD, MCX, or INDICES for indices |
| `lhs_tradingsymbol` | string | yes |  | tradingsymbol of the monitored instrument: INFY, 'NIFTY 50' |
| `operator` | `<=` \| `>=` \| `<` \| `>` \| `==` | yes |  | comparison of the monitored value with the right-hand side |
| `rhs_type` | `constant` \| `instrument` | yes |  | constant: compare with rhs_constant. instrument: compare with another instrument (rhs_*) |
| `rhs_constant` | number (optional) |  | `null` | the number to compare with (INR for prices); only for rhs_type=constant |
| `rhs_exchange` | `NSE` \| `BSE` \| `NFO` \| `CDS` \| `BCD` \| `MCX` \| `INDICES` (optional) |  | `null` | only for rhs_type=instrument |
| `rhs_tradingsymbol` | string (optional) |  | `null` | only for rhs_type=instrument |
| `rhs_attribute` | string (optional) |  | `null` | only for rhs_type=instrument; defaults to LastTradedPrice |
| `lhs_attribute` | string |  | `"LastTradedPrice"` | what to monitor; LastTradedPrice is the only attribute Kite documents |
| `orders` | array of AlertOrder (optional) |  | `null` | the basket of orders: required for type=ato (up to 20), not allowed for simple |
| `dry_run` | boolean |  | `true` | true (default): validate and preview only, nothing is sent. false: send it live, which needs live trading enabled on the server and the confirmation_token from a dry run |
| `confirmation_token` | string (optional) |  | `null` | the confirmation_token returned by a dry run of this exact call (single use) |

### `modify_alert`: Modify an alert (dry run by default)

*write*

Modify an alert. Kite replaces the whole alert, so send its complete new definition: call get_alert first
and change only what you mean to change. The fields are those of create_alert, with the same rules (for an ato
alert that includes the whole basket `orders`). DRY RUN BY DEFAULT, confirmed like create_alert.

order count, but the full value of the new basket counts toward the day's value cap. The dry run shows the
stored alert. Kite's docs do not say whether a basket sent here replaces the stored basket or adds to it, so
the dry run warns when the alert already has one. Returns the updated alert when sent.

| `lhs_tradingsymbol` | string | yes |  | tradingsymbol of the monitored instrument: INFY, 'NIFTY 50' |
| `operator` | `<=` \| `>=` \| `<` \| `>` \| `==` | yes |  | comparison of the monitored value with the right-hand side |

`instalments`, -1 should mean until cancelled (see place_mf_sip).

LEGACY ROUTE: Kite's current documentation lists no way to place, change or cancel mutual-fund orders or SIPs, and
says "Order placement can't be done, as order placement needs payment from the user's bank account". Kite may reject
this request. This tool exists only because KITE_MCP_ALLOW_MF_WRITES=true; check get_mf_orders / get_mf_sips
afterwards.

| `amount` | number (optional) |  | `null` | new INR per instalment, up to 2 decimals |
| `status` | `active` \| `paused` (optional) |  | `null` | paused to pause the SIP, active to resume it |
| `instalments` | integer (optional) |  | `null` | new number of instalments, or -1 to run until cancelled |

| `instalment_day` | integer (optional) |  | `null` | monthly SIPs only: day of the month (1, 5, 10, 15, 20 or 25) |
| `dry_run` | boolean |  | `true` | true (default): validate and preview only, nothing is sent. false: send it live, which needs live trading enabled on the server and the confirmation_token from a dry run |
| `confirmation_token` | string (optional) |  | `null` | the confirmation_token returned by a dry run of this exact call (single use) |

## margins

### `get_order_margins`: Margin required for orders

*calc*

Margin Kite would block for each of 1 to 50 orders, without placing anything (works in read-only mode too).

Every order is priced on its own, taking your existing positions and open orders into account; to price
orders as one package (hedge or spread benefit) use get_basket_margins. All amounts are INR. Each entry has
type (equity or commodity), span, exposure, option_premium, additional, bo, cash, var, pnl, leverage, charges
and total, the margin to block. mode=compact returns the totals only. Leave price at 0 for MARKET and SL-M
orders. `summary` adds up the totals and the charges.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `orders` | array of MarginOrder | yes |  | 1 to 50 orders |
| `mode` | string (optional) |  | `null` | compact: only the totals; omit for the full breakdown |

### `get_basket_margins`: Margin required for a basket of orders

*calc*

Margin for 1 to 50 orders taken together as one basket, without placing anything (also in read-only mode).

`initial` is the total margin required to execute the orders, `final` the total margin with the spread
(hedge) benefit, `orders` the per-order margins, and `charges` Kite's overall charges block, which can leave
out the transaction tax when MCX and equity orders are mixed: use the per-order charges instead. All amounts
are INR. mode=compact returns the totals only. `summary` gives the initial and final margin, the spread
benefit (initial minus final) and the summed per-order charges.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `orders` | array of MarginOrder | yes |  | 1 to 50 orders |
| `consider_positions` | boolean |  | `true` | true (default): net the basket against your open positions; false: price it alone |
| `mode` | string (optional) |  | `null` | compact: only the totals; omit for the full breakdown |

### `get_order_charges`: Charges for orders (virtual contract note)

*calc*

Charges Kite would levy on 1 to 50 executed or imaginary orders (a virtual contract note), without
placing anything (works in read-only mode too): brokerage, transaction tax (STT, or CTT on commodities),
exchange and SEBI turnover charges, stamp duty and GST, all INR.

Give each order's average_price (the price it was or would be executed at; must be above 0); order_id can
be any string. Each entry in `orders` is Kite's answer for one order: the order's fields, the price used and
a `charges` block (total plus the breakdown). `summary` has the grand total, the total per component and a
line per order.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `orders` | array of ChargeOrder | yes |  | 1 to 50 orders |

## ticker

### `ticker_subscribe`: Stream live ticks

*local*

Start streaming live market data for instruments over Kite's WebSocket. The server opens one connection in
the background on the first call (it needs the paid Kite Connect plan and a current login), reconnects and
resubscribes by itself, and keeps the latest tick of every subscribed instrument for ticker_get_ticks.

Modes: ltp (last price), quote (default: last price, last quantity, average price, volume, buy/sell quantity,
OHLC, change %), full (quote plus open interest, last trade time, exchange timestamp and 5 levels of bid/offer
depth). Indices have no volume or depth. Subscribing an instrument again with another mode switches its mode.
At most KITE_MCP_TICKER_MAX_SUBSCRIPTIONS instruments (default 1000; Kite allows 3000) can be subscribed.

An empty instruments list only opens the connection, which is how to receive order updates
(ticker_order_updates) without market data. This changes only the server's own streaming state; it places no
orders.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `instruments` | array of string \| integer | yes |  | EXCHANGE:TRADINGSYMBOL names (NSE:INFY, NSE:NIFTY 50, NFO:NIFTY25NOVFUT) and/or numeric instrument tokens (408065). Names are looked up in the instrument list; if that cannot be loaded, use tokens. |
| `mode` | `ltp` \| `quote` \| `full` |  | `"quote"` | ltp = last price only; quote = price, volume, OHLC, buy/sell quantity; full = quote plus open interest and 5-level market depth |

### `ticker_unsubscribe`: Stop streaming instruments

*local*

Stop streaming instruments and drop their cached ticks. Instruments that were not subscribed are listed
under not_subscribed. The WebSocket connection stays open (order updates keep arriving); ticker_stop closes
it.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `instruments` | array of string \| integer | yes |  | EXCHANGE:TRADINGSYMBOL names (NSE:INFY, NSE:NIFTY 50, NFO:NIFTY25NOVFUT) and/or numeric instrument tokens (408065). Names are looked up in the instrument list; if that cannot be loaded, use tokens. |

### `ticker_get_ticks`: Latest cached ticks

*read*

The latest tick received for each subscribed instrument, from the server's cache (nothing is requested from
Kite). Each tick has instrument (when known), instrument_token, mode, last_price and, for quote and full,
last_traded_quantity, average_traded_price, volume_traded, total_buy_quantity, total_sell_quantity,
ohlc {open, high, low, close} and change (% from the previous close); full adds oi, oi_day_high, oi_day_low,
last_trade_time, exchange_timestamp and depth {buy, sell} (5 levels of {quantity, price, orders}). Prices are
in rupees, times in IST. Every tick also has received_at and age_s (seconds since it arrived): ticks stop
outside market hours or when the connection is down, so check age_s, or pass max_age_s to be told which
instruments are stale. Instruments subscribed but without a tick yet are listed under no_tick_yet.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `instruments` | array of string \| integer (optional) |  | `null` | which instruments (names and/or tokens); default: every subscribed instrument |
| `max_age_s` | number (optional) |  | `null` | leave out ticks older than this many seconds; they are listed under stale |

### `ticker_status`: WebSocket ticker status

*read*

The state of the WebSocket ticker: state (idle, connecting, connected, retrying, waiting_for_login, blocked,
failed), connected, connected_since, last_message_at (any frame, heartbeats included), last_tick_at,
reconnects, subscriptions by mode, how many ticks and order updates are cached, packets_skipped (frames this
server could not parse), last_error, and blocked (why the ticker stopped retrying: Kite refused the token, for
example because the app has no paid WebSocket plan). Nothing in it is secret.

### `ticker_order_updates`: Order updates and broker messages

*read*

Order updates and broker messages received by this server: the WebSocket stream (live updates for orders
placed anywhere on the account: web, mobile or API) and, when KITE_MCP_POSTBACK_PATH is set, Kite postbacks
sent to the HTTP endpoint. Each item has seq, received_at, source ("ticker" or "postback"), type ("order";
"error" or "message" for Kite's own text) and data. For orders, data has order_id, status (COMPLETE, REJECTED,
CANCELLED, UPDATE...), status_message, exchange, tradingsymbol, transaction_type, order_type, product, variety,
quantity, filled_quantity, pending_quantity, price, trigger_price, average_price and timestamps.

Only the last 500 items are kept, in memory, and items arrive only while the WebSocket is open
(ticker_subscribe, even with an empty list, opens it) or the postback endpoint is receiving. Without since:
the latest items, oldest first. With since: the first items after it, so you can page forward (more=true
means there are further ones). These are notifications, not the book of record: a postback is authenticated
only by a checksum over order_id and order_timestamp, so confirm what matters with get_order_history.

| Argument | Type | Required | Default | Description |
|---|---|---|---|---|
| `limit` | integer |  | `50` | at most this many items |
| `since` | string (optional) |  | `null` | ISO 8601 time (IST if no offset): only items received after it, oldest first |

### `ticker_stop`: Stop the WebSocket ticker

*local*

Close the WebSocket connection and forget all subscriptions and cached ticks (order updates already
received stay available). Calling ticker_subscribe later starts afresh, which is also how to retry after Kite
refused the connection with the current token. Safe to call when nothing is running.

## safety

### `get_safety_status`: Safety settings and today's usage

*read*

How this server guards writes: trading mode (dry_run or live), read-only, how live writes are confirmed,
the per-order / daily value caps and order count, the allow-lists, whether the kill switch is on, and what has
been sent live today (counted from the audit log). Call this before planning any order.

### `get_audit_log`: Audit log of write attempts

*read*

The audit log: every dry run, refusal, confirmation, live send and its result, oldest first (newest

| Argument | Type | Required | Default | Description |

| Argument | Type | Required | Default | Description |

| `reason` | string | yes |  | why writes are being stopped |
